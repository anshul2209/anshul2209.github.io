Platform work

Selected threads from recent years at OLX India — how the work was approached, not just the outcomes.

Edge caching and bot classification

A blanket TTL treated humans, search crawlers, and abusive bots the same — either over-caching stale inventory or under-caching and burning origin. We classified traffic at the edge and gave each class its own cache and block policy by page type. The hard part was false positives on legitimate crawlers; the tradeoff was operational complexity at Akamai in exchange for origin headroom and cleaner crawl budgets.

SEO at scale

Organic growth was capped by crawl waste: expired listings returned 404s, zero-inventory categories still got crawled, and rendering cost competed with indexable HTML. We fixed the technical foundation first — redirects, suppression, and crawl efficiency — then moved into on-page quality. Written up in two parts on tech.olx.in.

AI discoverability

Making the site legible to LLM crawlers: robots.txt Content-Signal directives, an llms.txt, and Markdown content negotiation so agents can pull structured answers without scraping the full PWA shell.

Trunk-based development with session flags

Long-lived feature branches were slowing delivery and making production risk hard to reason about. Session-scoped flags in the SSR pipeline let the team merge small changes continuously without exposing unfinished work — written up on tech.olx.in.

ReviewOwl

GitLab CI + Slack bot for automated MR reviewer assignment with load-aware round-robin, so review load stays balanced across the web chapter without manual routing.

OLX Assist

Workflow-based chat widget for help.olx.in — JS SDK embed, cookie/Bearer auth, and XMPP triggers — so support flows can sit inside the help surface without a separate app shell.
